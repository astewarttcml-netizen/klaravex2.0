# T14.39 — Fix Hetzner Default vhost Rebrand Leak

**Priority:** High | **Type:** Security | **Scope:** nginx default vhost hardening

---

## Background & Risk

The current nginx configuration on the Hetzner node:

- Serves a catch-all vhost that **leaks the `api.klaravex.com` hostname** via redirect on unknown `Host:` headers
- Allows host-header enumeration / rebrand fingerprinting
- May expose internal routing topology to passive observers

**Fix:** Drop all connections with unrecognised `Host` headers using nginx's `444` (silent close, no response).

## Step 1 — Backup Existing Configuration

```bash
# Timestamped backup of entire nginx config tree

# Confirm backup exists
ls -lhd /etc/nginx.bak.*
```

## Step 2 — Locate & Audit the Offending Default vhost

```bash
# Find the current default_server declaration
grep -rn "default_server\|api\.klaravex\.de\|return 301\|return 302" \
    /etc/nginx/sites-enabled/ /etc/nginx/conf.d/ 2>/dev/null

# Show full file(s) for review
cat /etc/nginx/sites-enabled/default   # adjust path if different
```

> **Note the filename** returned above — substitute it for `<DEFAULT_VHOST_FILE>` below.

---

## Step 3 — Write the Hardened Default vhost

```bash
# Write new catch-all drop vhost
sudo tee /etc/nginx/sites-available/00-default-drop.conf > /dev/null << 'EOF'
# ---------------------------------------------------------------
# T14.39 — Default catch-all: drop unknown Host headers silently
# Deployed: auto-stamped by deployment script
# ---------------------------------------------------------------

# IPv4 — HTTP
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    # TLS catch-all (requires a self-signed or wildcard cert)
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;

    # Minimal self-signed cert to absorb TLS ClientHello without
    # leaking a real cert. Generate once (see Step 4).
    ssl_certificate     /etc/nginx/ssl/default-drop.crt;
    ssl_certificate_key /etc/nginx/ssl/default-drop.key;

    # Reject all — no response body, connection closed immediately
    return 444;

    # Suppress access logging for noise reduction (optional)
    access_log /var/log/nginx/default-drop-access.log combined;
    error_log  /var/log/nginx/default-drop-error.log  warn;
}
EOF
```

---

## Step 4 — Generate Throwaway Self-Signed Certificate

> Required so nginx can bind `443 default_server` without a real cert leaking hostname info.

```bash
sudo mkdir -p /etc/nginx/ssl

sudo openssl req -x509 -nodes -newkey rsa:2048 \
    -keyout /etc/nginx/ssl/default-drop.key \
    -out    /etc/nginx/ssl/default-drop.crt \
    -days   3650 \
    -subj   "/CN=invalid" \
    2>/dev/null

sudo chmod 600 /etc/nginx/ssl/default-drop.key
sudo chmod 644 /etc/nginx/ssl/default-drop.crt
```

## Step 5 — Disable the Old Default vhost

```bash
# Disable the old default (do NOT delete yet — rollback safety)
sudo unlink /etc/nginx/sites-enabled/default 2>/dev/null || true

# Also disable any conf.d file that contained the redirect

# sudo mv /etc/nginx/conf.d/default.conf /etc/nginx/conf.d/default.conf.disabled
```

---

## Step 6 — Enable the New Drop vhost

```bash
sudo ln -sf \
    /etc/nginx/sites-available/00-default-drop.conf \
    /etc/nginx/sites-enabled/00-default-drop.conf
```

> The `00-` prefix ensures this file sorts **first** and wins the `default_server` race.

## Step 8 — Smoke Tests

```bash
TARGET_IP="<HETZNER_NODE_IP>"   # substitute real IP

# 1. Unknown Host → expect: empty reply (444 = connection closed)
curl -sv --max-time 5 \
    -H "Host: attacker.example.com" \
    "http://${TARGET_IP}/" 2>&1 | grep -E "< HTTP|Empty reply|Connection reset"

# 2. Unknown Host over TLS → expect: connection closed / SSL error (no cert leak)
curl -svk --max-time 5 \
    -H "Host: attacker.example.com" \
    "https://${TARGET_IP}/" 2>&1 | grep -E "< HTTP|Empty reply|SSL|Connection reset"

# 3. Legitimate vhost still responds (substitute real hostname)
curl -sv --max-time 5 \
    -H "Host: api.klaravex.com" \
    "https://${TARGET_IP}/" 2>&1 | grep "< HTTP"

# 4. Confirm NO redirect to api.klaravex.com leaks on unknown Host
curl -sv --max-time 5 \
    -H "Host: probe.invalid" \
    "http://${TARGET_IP}/" 2>&1 | grep -i "location"
# Expected output: (empty — no Location header)
```

**Expected results:**

| Test | Expected |
|------|----------|
| Unknown Host HTTP | `Empty reply from server` or `Connection reset` |
| Unknown Host HTTPS | SSL handshake error / connection closed |
| Legitimate Host | `HTTP/1.1 200` (or appropriate app response) |
| Location header on unknown Host | *(empty — nothing leaked)* |

## Rollback Procedure

> Execute if smoke tests fail or legitimate traffic is impacted.

```bash
# 1. Remove the new drop vhost symlink
sudo unlink /etc/nginx/sites-enabled/00-default-drop.conf

# 2. Re-enable the old default vhost
sudo ln -sf \
    /etc/nginx/sites-available/default \
    /etc/nginx/sites-enabled/default

# 3. Syntax check & reload
sudo nginx -t && sudo systemctl reload nginx

# 4. Verify rollback
sudo systemctl status nginx --no-pager
curl -sv -H "Host: probe.invalid" "http://<HETZNER_NODE_IP>/" 2>&1 | head -20
```

> Full config restore from timestamped backup (nuclear option):
> ```bash
> sudo systemctl stop nginx
> sudo rm -rf /etc/nginx
> sudo cp -a /etc/nginx.bak.<TIMESTAMP> /etc/nginx
> sudo systemctl start nginx
> ```
