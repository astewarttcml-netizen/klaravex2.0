# Loki AI Support Agent — Security, Compliance, and Operational Risk

_All findings from WebSearch results._

## 1. LLM Security Risks — Prompt Injection, Data Leakage, Hallucinated Advice
Prompt injection is the primary threat (direct jailbreak + indirect via malicious content in tickets/files). LLMs cannot reliably separate instruction from data. 2026 posture has shifted to **containment architecture**: even if injection succeeds, the agent must have no write access to client systems, no credential stores, no command execution without explicit human approval. Data leakage compounded by multi-tenant history access without strict tenant isolation. Hallucinated technical advice is especially dangerous for an MSP — 63% of production AI agent deployments hit dangerous hallucinations within 90 days (Maxim.ai 2026). Guardrails cutting hallucination 71–89% require: Graph-RAG grounded in a verified KB, neurosymbolic rule enforcement (never recommend destructive actions w/o human confirmation), multi-agent validation for high-stakes outputs, output-layer filtering before responses reach the client.

## 2. HIPAA — Hetzner is NOT HIPAA-Eligible Infrastructure
Any AI agent processing PHI (names, DOB, diagnosis hints, free-text symptoms) is a Business Associate under HIPAA and requires a BAA with every vendor in the chain: LLM API provider, hosting provider, observability platform. BAA-signing LLM providers (2025): OpenAI Enterprise, Anthropic API Enterprise, Google Workspace Enterprise. **Hetzner is not HIPAA-eligible** — holds ISO/IEC 27001:2022, GDPR-compliant, but offers no HIPAA certification and will not sign a BAA. Running PHI through Loki on Hetzner CX22 — even with a HIPAA-eligible LLM API — breaks chain of custody because the compute layer assembling prompts/parsing responses is non-compliant. Remediation before any healthcare-adjacent client: (a) PHI redaction/de-identification at intake so no identifiable health data enters Hetzner, OR (b) migrate Loki to AWS/Azure/GCP with a signed BAA. Secondary issue: Hetzner (Falkenstein/Nuremberg) responds only to German legal authority — US subpoenas not honored — complicating US incident response and legal-hold obligations.

## 3. Escalation Design — Confidence Thresholds + Handoff
Regulated industries: confidence threshold for autonomous resolution 90–95%; below that escalate or flag for async review. Tiered: >85% autonomous; 70–85% proceed but flag; <70% escalate synchronously before responding. **Hard-trigger rules independent of confidence:** credential resets, firewall changes, data deletion, backup manipulation → human unconditionally. Client requests for a human honored with zero friction/zero retry loops — ignoring this is the fastest trust-destroyer. Warm handoff (full transcript + AI summary) >> cold transfer. Healthy escalation 10–15%; <5% = under-escalation; >30% = KB/model failure. Treat escalation policy as living config, measured monthly.

## 4. Observability and Audit Logging
Production AI agents require structured logging of the full execution chain: every model invocation, tool call, retrieval query, memory read/write, decision branch — with causal traces. Regulated-MSP audit log must capture: full prompt sent, full response, KB docs retrieved (source IDs), action taken, timestamp + client/session ID. **PII/PHI in logs must be redacted at write time** — storing raw PHI transcripts in non-HIPAA-eligible Postgres is a violation regardless of where the LLM runs. Monitor guardrail telemetry — a spike signals active injection campaign or KB poisoning. Wrong-resolution detection: correlate AI-resolved interactions with ticket reopens within 24h. Self-hostable observability for Hetzner co-deploy (when no PHI flows): MLflow, Langfuse, Braintrust.

## 5. Liability — Wrong Advice, Disclaimers, Human-in-the-Loop
Courts/regulators reject "AI did it" — AI-generated statements are company representations, exposing the MSP to FTC enforcement, state deceptive-practices claims, and E&O suits if advice causes harm. 2025 state laws for healthcare-adjacent clients require: (a) disclosure that a response is AI-generated; (b) explicit human-alternative instructions. Disclaimers reduce but don't eliminate liability; no defense against gross negligence/systematic misconfiguration. ≥6 US states enacted AI chatbot laws in 2025; EU AI Act high-risk obligations activate Aug 2026. Mitigations: Loki never executes system-modifying actions autonomously; all technical instructions carry visible "AI-assisted — verify before acting"; E&O explicitly confirmed to include AI-assisted support; client MSA defines scope/limitations of AI first response.

## 6. Reference Architecture — RAG-Based AI Support for MSPs
Dominant 2025–26 pattern: RAG over a curated, access-controlled KB. Strict tenant isolation at retrieval layer is mandatory — Client A data never retrievable in Client B's session. Dual-store (vector for semantic + structured Postgres for deterministic) beats vector-only for technical accuracy. Pipeline: intake → input guardrails (PII/injection detection) → RAG retrieval (tenant-scoped) → LLM inference (HIPAA-eligible API if PHI possible) → output guardrails (PII redaction, destructive-action filter, confidence check) → response OR escalation → full trace logged. MCP emerging as 2026 standard for structured, audit-logged, permissioned tool calls — preferable to raw function calling for compliance. **Immediate blocking requirement for Loki before any HIPAA-adjacent client: PHI redaction at intake OR migration to HIPAA-eligible hosting.**
