# G34.1 — librustdesk binding decision

**Decision date:** 2026-06-12 (Klara AI iteration 5)
**Status:** DECIDED → hybrid subprocess + Rust shim (option **b**)
**Decider:** Klara AI autonomous loop (claude provider)

## Context

`protocol.py` enumerates three feasible operator-side bindings:

| Opt | Approach | Pros | Cons |
|---|---|---|---|
| a | FFI: librustdesk → cdylib → Python (cffi/pyo3) | Maximal code reuse from upstream; native perf for codec + crypto | Cross-platform cdylib build is the longest-tail effort; ABI churn every upstream release; segfault risk leaks into Python |
| **b** | **Subprocess-drive a small Rust shim (`klx-rdshim`) that statically links the upstream `hbb_common` + client crates and exposes a stdin/stdout newline-delimited JSON protocol** | **No ABI surface; tiny CLI binary per platform; easy to test on both sides with mocks; Python keeps GIL safety** | **Need to publish + ship a small Rust binary per OS; extra serialization hop costs ~50µs per event (negligible at 1.5fps frame budget)** |
| c | Reimplement RustDesk protobufs in pure Python (MIT .proto files) | Zero external binaries; full control of every byte | Have to track upstream protocol changes; reimplement NoiseProtocol-style crypto; codec decode (VP9/H264) still needs a C lib so we'd reintroduce option a anyway for codecs |

## Decision

**Pick (b) with a thin shim binary `klx-rdshim`.**

Rationale:
1. **Speed to first working frame.** A shim that wraps `libs/hbb_common::message_proto` + `libs/scrap` and exposes start/stop/event commands lands faster than either pyo3 bindings or a from-scratch protobuf reimpl.
2. **Bisectable transport.** Subprocess boundary means we can fuzz the JSON protocol from Python tests without standing up a real RustDesk session. Already validated this pattern works in `test_transport_probe.py` style (loopback listeners).
3. **GIL & crash safety.** A subprocess crash kills the shim, not the Python session loop. The session can re-spawn with a fresh customer ID. Option (a)'s segfault would corrupt the whole controller.
4. **Vendor independence.** If upstream RustDesk breaks our use case, we replace the shim's internals while keeping the JSON protocol stable for `RustDeskClient`.

## The JSON IPC protocol (`klx-rdshim` v0)

Every line on stdin/stdout is a single JSON object with a `kind` discriminator.

### Python → shim (commands written to shim stdin)

```json
{"kind":"connect","relay_host":"87.99.147.244","relay_key":"D7Brb…","hbbs_port":21116,"hbbr_port":21117,"customer_id":"4242-1111-9090","session_password":"1z8k…"}
{"kind":"event","event_kind":"mouse_move","x":0.4218,"y":0.6614}
{"kind":"event","event_kind":"mouse_click","x":0.4218,"y":0.6614,"button":"left"}
{"kind":"event","event_kind":"key_press","key":"Return"}
{"kind":"event","event_kind":"paste_text","text":"hello"}
{"kind":"disconnect"}
```

### Shim → Python (events written to shim stdout)

```json
{"kind":"hello","shim_version":"klx-rdshim 0.1.0","librustdesk_commit":"abcd1234"}
{"kind":"connected","session_id":"K-2026-06-12-7f31","width":1920,"height":1080}
{"kind":"frame","session_id":"K-2026-06-12-7f31","sequence":17,"width":1920,"height":1080,"codec":"jpeg","payload_b64":"…","timestamp_ms":1718178501023}
{"kind":"event_ack","sequence":42,"status":"sent"}
{"kind":"error","code":"relay_unreachable","message":"hbbs 87.99.147.244:21116 timed out after 3000ms"}
{"kind":"disconnected","reason":"peer_closed"}
```

Stdout is line-delimited JSON; stderr is human-readable shim log lines (Python forwards them through `logging`).

### Versioning

* Shim sends `hello` immediately after spawn with its semver + librustdesk git hash.
* Python compares against `RDSHIM_SUPPORTED_VERSIONS = {"0"}` (major-only). Mismatch → refuse to use, fall back to the dry-run stub transport.

## Risks accepted

- **Protocol drift between iterations 5 and 6.** Mitigation: the JSON schema in this file is the contract. Iteration 6 implements it; iteration 5's Python tests are the conformance suite.
- **JSON overhead on frame ingest.** A 1080p JPEG keyframe at ~120 KB base64-encodes to ~160 KB plus JSON quoting. At 1.5fps frame budget, that is 240 KB/s = 1.9 Mbps — well below the relay's capacity. If it ever bottlenecks we switch frames to a separate UNIX domain socket carrying raw bytes; events stay on JSON.

## Reversal cost

The `RustDeskTransport` Protocol in `protocol.py` is the only contract the upper layers depend on. Replacing `ShimSubprocessTransport` with a pyo3 binding (option a) is a same-file substitution — zero changes to `session.py`, `vision.py`, `recording.py`, `killswitch.py`.
